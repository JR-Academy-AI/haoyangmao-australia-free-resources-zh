虚构示例：课程 Web 项目只先选 GitHub 与 JetBrains；Azure 留到课程确需部署时。申请状态均为待个人在官方核实，不是已获批。

任务：代码托管与项目协作
工具／选择：GitHub Student Developer Pack
需确认条件：须通过 GitHub Education 在读学生验证；年龄及证明材料按官方要求。合作方可能另外审核。；工具包通过不代表所有合作方权益自动开通；领取窗口和服务额度可能不同。
下一步：先在官方 Education 页面查看当前学生验证要求，准备提供方接受的在读证明。证明只交给官方，不上传本站或 GitHub Issue。 → 通过自己的 GitHub 账号申请学生身份，按官方页面处理验证；本指南不代办或保证审批。 → 通过后打开 Pack，逐项查看所需合作方的领取窗口、额度与续费条款，再决定是否开通。 → 将课程仓库按老师要求设定可见性和成员权限，不公开学校不允许公开的作业、密钥或同学资料。
官方来源：https://education.github.com/pack

任务：编写、调试课程代码
工具／选择：JetBrains 教育许可
需确认条件：认可教育机构的学生或教师，需提供有效教育身份证明；许可证不用于商业工作。；毕业或不再符合资格后需重新核对授权；商用要使用相应商业许可。
下一步：确认自己属于官方接受的学生或教师范围，并核对教育许可条款。 → 通过官方 Student Pack 页面选择可用验证方式，使用自己的身份申请。 → 只安装课程需要的 IDE，按自己设备与项目语言选择版本。 → 记录许可到期与续期要求；接客户项目、实习交付或毕业后使用前重新核对授权。
官方来源：https://sales.jetbrains.com/hc/en-gb/articles/207241195-Do-you-offer-free-educational-licenses-for-students-and-teachers

任务：练习云端部署
工具／选择：Azure for Students
需确认条件：面向符合官方验证要求的全日制大学生；每人账户及验证规则以官方为准。申请不要求信用卡。；额度用尽或到期后的处理、可用服务和续期条件须到官网确认；不要自行升级付费方案。
下一步：在 Azure for Students 页面确认学生资格、学校验证、服务目录及当前有效期，不套用普通付费账户条款。 → 通过官方学生入口申请，阅读账户类型，避免误选其他商业或付费方案。 → 创建资源前查看实际区域、规格和计费说明，给练习设定自己的使用上限；预警不等于绝对停止扣费。 → 练习结束后核对并删除不再需要的资源，检查账户状态与资格变化，保留自己需要的代码。
官方来源：https://azure.microsoft.com/en-au/free/students

任务：设计课程原型与协作
工具／选择：Figma 教育方案
需确认条件：须满足 Figma 对在读学生、教育工作者、课程及支持地区的要求，并完成教育验证。；教育权益不自动覆盖全部 AI、开发者或商业产品；以当前计划说明为准。
下一步：查看官方 Education 资格说明，确认课程是有结构的教育场景，并核对适用地区、年龄与身份要求。 → 在自己的官方账号验证教育身份，按官方流程建立或加入教育团队。 → 确认同组成员、文件归属与共享权限；先用少量课程文件验证协作方式。 → 把课程使用与客户、机构内部商业培训或收费交付分开，付费附加能力按计划说明核实。
官方来源：https://help.figma.com/hc/en-us/articles/360041061214-Figma-for-Education

任务：整理个人课程资料
工具／选择：Notion 教育方案
需确认条件：符合官方要求的高校学生或教师，使用认可学校邮箱；个人教育工作区通常要求仅一名 member。；不把 AI 功能或所有团队功能视为随教育方案无限免费。
下一步：确认高校和学校主邮箱符合官方要求，检查邮箱仍可接收年度验证；备用学校邮箱不等于主邮箱。 → 检查目标工作区是否只有自己一名 member，并阅读计划变更对教育资格的影响，先保存需要的资料，不盲目删除成员。 → 在桌面或网页设置中查看升级计划及免费教育入口；按页面实际状态操作。 → 小组协作先核对 guest 权限，正式学生组织有单独规则。毕业或学校邮箱不可用后重新评估计划。
官方来源：https://www.notion.com/help/notion-for-education
