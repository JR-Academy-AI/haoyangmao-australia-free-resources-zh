## 课程 Web 项目：先配齐协作与开发环境

虚构场景：在澳在读学生“小林”准备非商业课程项目，需要提交一个图书借阅网页的代码与说明。没有真实学生、审批结果或已部署项目。

### 任务与交付边界

课程目标是提交代码、运行说明和测试记录。方案只解决工具选择与申请准备；代码仍要自己完成，不能把拿到许可当作完成项目。

### 工具分工与选择

GitHub 用于仓库、变更记录和组内协作；课程要求的 IDE 用 JetBrains 教育许可。若现有免费编辑器已满足作业，不必额外申请。Azure 延后：先本机运行，只有老师要求远程部署时才核对学生账户。

### 申请准备清单

核对 GitHub 在读证明要求；在官方 JetBrains 页面核对认可身份；确定学校允许的代码可见性；检查电脑操作系统；准备自己的账号，不分享密码或把证明交给薅羊毛。

### 实际安排

第一步核对课程提交规则；第二步在本机跑通基础项目；第三步在官方申请所需教育权益；第四步邀请组员到课程仓库并约定分支；第五步在 README 写出安装、运行、测试和分工说明。

### 许可与费用决策

课程仓库不代表全部内容可公开。JetBrains 教育许可不用于商业工作。GitHub 合作权益分别有期限，未需要的服务不开通；云资源未开通，不把额度算作节省现金。

### 如果没有通过

继续使用课程允许的现有工具；向相应官方支持核对原因，不伪造学生证明、不重复创建账号领取。未获批就保持“待确认”，不写成已经领取。

### 完成后的判断

能解释每个工具用途、申请路线和许可限制，能列出自己的下一步；是否通过验证由提供方决定，是否完成项目靠实际作业验收。

## 小组原型课：资料结构与协作权限一次理清

虚构场景：三位学生做“校园失物招领”课程原型。以下是预生成编辑方案和文字资料结构，不是已创建的 Notion 工作区或 Figma 文件。

### 任务与最终提交

小组提交四个界面：失物列表、筛选结果、物品详情、联系说明。原型只演示界面，不发送真实消息，不收录真实姓名、电话或失物照片。

### 工具选择

Figma 用于课程原型；先核对所有成员与教育团队条件。Notion 用于个人资料整理，个人教育工作区不等于三人免费 member 团队；协作先查 guest 的权限和限制。

### 已填好的资料结构

课程要求：列表必须支持类别筛选；资料来源：Figma 官方教育说明、Notion 官方教育帮助；决定记录：原型不包含真实联系信息；任务表：A 同学画列表与筛选、B 同学画详情与联系说明、C 同学核对文案与可访问性；提交清单：四页原型、交互路线文字稿、来源与分工说明。A／B／C 均为虚构角色。

### 交互路线文字稿

访客打开失物列表 → 选择“文具” → 看见虚构物品“蓝色笔袋” → 打开详情阅读“教学演示，无真实招领” → 打开联系说明看到“本示例不发送消息”。不放失效外链冒充真实作品。

### 申请与权限顺序

先核对课程与教育资格 → 各自在官方验证 → 确认 Figma 团队与文件归属 → 用一份无个人信息的课程文件试权限 → 在 Notion 检查 member 与 guest 区别后再邀请协作。

### 不适合的情况

客户交付、商业团队或无法核实教育资格时，不沿用课堂权益结论。涉及 Notion 计划升级、成员变更时，先读官方对教育资格的影响并保留资料。

### 下一步与验收

按文字结构建立自己的资料与原型，核对老师要求。这里交付的是完整选择和组织方案，不承诺原型已制作、工具已开通或课程成绩。

## GitHub Student Developer Pack

需要版本记录和小组协作时先用 GitHub；只领取项目用得上的合作权益，不为用满工具包分散精力。

资格：须通过 GitHub Education 在读学生验证；年龄及证明材料按官方要求。合作方可能另外审核。

限制：工具包通过不代表所有合作方权益自动开通；领取窗口和服务额度可能不同。

1. 先在官方 Education 页面查看当前学生验证要求，准备提供方接受的在读证明。证明只交给官方，不上传本站或 GitHub Issue。
2. 通过自己的 GitHub 账号申请学生身份，按官方页面处理验证；本指南不代办或保证审批。
3. 通过后打开 Pack，逐项查看所需合作方的领取窗口、额度与续费条款，再决定是否开通。
4. 将课程仓库按老师要求设定可见性和成员权限，不公开学校不允许公开的作业、密钥或同学资料。

遇到问题：身份或合作权益没有通过时，从 Education 帮助与对应合作方的支持入口核对原因，不重复注册或伪造证明。

## JetBrains 教育许可

课程确实使用 JetBrains IDE 时申请；已能完成作业的现有编辑器也可以继续用，不必为了免费更换整套工具。

资格：认可教育机构的学生或教师，需提供有效教育身份证明；许可证不用于商业工作。

限制：毕业或不再符合资格后需重新核对授权；商用要使用相应商业许可。

1. 确认自己属于官方接受的学生或教师范围，并核对教育许可条款。
2. 通过官方 Student Pack 页面选择可用验证方式，使用自己的身份申请。
3. 只安装课程需要的 IDE，按自己设备与项目语言选择版本。
4. 记录许可到期与续期要求；接客户项目、实习交付或毕业后使用前重新核对授权。

遇到问题：免费教育许可不能用于商业工作；申请受阻时使用官方 Licensing FAQ 或支持入口核实，不共享或转售许可。

## Azure for Students

只有项目需要云端运行时才开通；本机能完成的作业先在本机做，云额度不是现金，也不是无限免费托管。

资格：面向符合官方验证要求的全日制大学生；每人账户及验证规则以官方为准。申请不要求信用卡。

限制：额度用尽或到期后的处理、可用服务和续期条件须到官网确认；不要自行升级付费方案。

1. 在 Azure for Students 页面确认学生资格、学校验证、服务目录及当前有效期，不套用普通付费账户条款。
2. 通过官方学生入口申请，阅读账户类型，避免误选其他商业或付费方案。
3. 创建资源前查看实际区域、规格和计费说明，给练习设定自己的使用上限；预警不等于绝对停止扣费。
4. 练习结束后核对并删除不再需要的资源，检查账户状态与资格变化，保留自己需要的代码。

遇到问题：验证、服务或额度有疑问时查看 Azure 学生页面 FAQ；不要主动转付费账户来绕过资格或额度限制。

## Figma 教育方案

需要共同编辑界面原型时再比较教育团队和普通免费层。学生身份、团队类型、使用目的都需单独核对。

资格：须满足 Figma 对在读学生、教育工作者、课程及支持地区的要求，并完成教育验证。

限制：教育权益不自动覆盖全部 AI、开发者或商业产品；以当前计划说明为准。

1. 查看官方 Education 资格说明，确认课程是有结构的教育场景，并核对适用地区、年龄与身份要求。
2. 在自己的官方账号验证教育身份，按官方流程建立或加入教育团队。
3. 确认同组成员、文件归属与共享权限；先用少量课程文件验证协作方式。
4. 把课程使用与客户、机构内部商业培训或收费交付分开，付费附加能力按计划说明核实。

遇到问题：教育验证或团队类型不符合时向 Figma 官方支持询问；不能借用其他学生身份建立商业团队。

## Notion 教育方案

个人笔记先看普通免费层是否够用；个人教育工作区只有一位 member，不能直接当作全组免费团队方案。

资格：符合官方要求的高校学生或教师，使用认可学校邮箱；个人教育工作区通常要求仅一名 member。

限制：不把 AI 功能或所有团队功能视为随教育方案无限免费。

1. 确认高校和学校主邮箱符合官方要求，检查邮箱仍可接收年度验证；备用学校邮箱不等于主邮箱。
2. 检查目标工作区是否只有自己一名 member，并阅读计划变更对教育资格的影响，先保存需要的资料，不盲目删除成员。
3. 在桌面或网页设置中查看升级计划及免费教育入口；按页面实际状态操作。
4. 小组协作先核对 guest 权限，正式学生组织有单独规则。毕业或学校邮箱不可用后重新评估计划。

遇到问题：教育入口不出现时按 Notion 官方帮助核对邮箱、学校和工作区；不把学生证上传本站代替官方邮箱验证。
